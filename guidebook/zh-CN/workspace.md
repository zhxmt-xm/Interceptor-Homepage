## 找到需要的工具

**用途与前提**：App 已完成启动准备，从左侧导航进入对应任务。

| 入口 | 用来做什么 |
| --- | --- |
| Capture | 观察经过代理的请求、正文和消息；处理挂起的断点 |
| Rules & Map | 按条件改变后续经过代理的流量 |
| Composer | 独立构造和发送请求，管理 Collection |
| Diagnostics | 查询 App 运行记录和失败原因 |
| Settings | 管理代理、证书、偏好、模型、MCP 与更新 |
| 窗口右上角 Agent 按钮 | 打开或关闭当前工作区旁的 AI 对话面板 |

**步骤**

1. 用窗口标题左边的菜单按钮展开侧栏，查看功能名称。

   ![实际展开的侧栏名称](../media/v0.1.1-alpha.1/workspace/workspace-01-sidebar.png)

2. 点击 Capture 进入流量工作区。

   ![实际 Capture 工作区](../media/v0.1.1-alpha.1/workspace/workspace-02-capture.png)

3. 点击 Rules & Map 进入规则。

   ![实际 Rules 工作区](../media/v0.1.1-alpha.1/workspace/workspace-03-rules.png)

4. 点击 Composer 进入请求构造器。

   ![实际 Composer 工作区](../media/v0.1.1-alpha.1/workspace/workspace-04-composer.png)

5. 点击 Diagnostics 查看运行记录。

   ![实际 Diagnostics 工作区](../media/v0.1.1-alpha.1/workspace/workspace-05-diagnostics.png)

6. 点击 Settings，再选择所需分组。

   ![实际进入 Settings](../media/v0.1.1-alpha.1/workspace/workspace-06-settings.png)

7. 离开 Settings 后再返回，核对保留的最后访问分组。

   ![离开后返回仍保留Privacy分组](../media/v0.1.1-alpha.1/workspace-navigation/workspace-navigation-04-return-settings.png)

8. 通过特定提示跳转 Settings 时，核对定位的分组，例如 TLS passthrough。

   ![从Capture快捷浮层直达Upstream](../media/v0.1.1-alpha.1/workspace-navigation/workspace-navigation-21-upstream-link.png)

   TLS透传的独立深链见[透传往返](settings.md#walkthrough-settings-tls-passthrough)，不把直接打开分组与快捷跳转混为一谈。

**预期结果**：窗口标题和主内容随选择变化；导航本身不会重发请求。

**关键说明**：Breakpoints 在 Capture 内，不是另一套独立导航。进入 Composer 或 Settings 不等于暂停 Capture；后台流量仍取决于 Recording、代理和规则状态。

## 哪些内容会保存

| 内容 | 需要记住的规则 |
| --- | --- |
| 当前 Capture 请求与正文 | 临时记录，Core 退出或重启会释放；重要数据先导出 |
| Rules | 编辑后需要 Apply；文件导入的确认流程会直接保存追加结果 |
| Composer Collection | 编辑自动保存；Recent sends 是另一份内存记录 |
| 代理、TLS 和其他偏好 | 按各自 Apply 或设置操作保存，不由 Capture Clear 清除 |
| Agent 配置和会话 | 在本地保存；模型调用及 Tool 结果仍可能发送到模型服务 |
| 导出的文件 | 保存在用户选择的位置；Clear 不会代你删除这些文件 |

**范围说明**：本段核对Collection名称/URL、Privacy与临时Capture。完整代表性请求的三级目录、method/protocol、Header值和启停、Query、JSON及公开Auth字段另有[保存](composer.md#walkthrough-composer-persistence-save)与[真实重启](composer.md#walkthrough-composer-persistence-restart)配对实录，重启不重填字段、不自动Send。Agent历史另见[会话重启](agent.md#walkthrough-agent-session-restart)；不把一段录像当作所有偏好或所有Body/Auth组合的穷举。

**操作建议**：退出前先完成导出、Apply 或正在进行的保存；不要仅凭屏幕还显示着数据就判断已经持久化。

不同系统账号或独立 App 数据环境之间不应假设集合和会话自动同步；当前系统用户的 CA 和代理恢复信息另有共享生命周期，不能通过随意删除 App 数据目录来重置它们。

## 正常结束一次使用

1. 处理或明确放弃仍挂起的断点，避免客户端一直等待。

   下图分别引用 Breakpoints 的单项原样放行和新 HTTP 队列中 POST-C/PUT-C 的批量放行，不冒充当前所有连接的全局状态；混合多个队列的全部清理仍待配图。

   ![实际原样放行一个断点](../media/v0.1.1-alpha.1/breakpoints/breakpoints-17-unmodified.png)

   ![实际批量处理本轮 HTTP 队列](../media/v0.1.1-alpha.1/breakpoints-queue/breakpoints-queue-24-continue-queue.png)

2. 导出需要保留的流量，等待文件任务完成。

   下图引用 Transfer 的 `guide-recording.iarchive` 完成检查点；不是自动保存整个工作区。

   ![实际归档保存完成](../media/v0.1.1-alpha.1/transfer/transfer-13-archive-complete.png)

3. 确认没有尚未处理的原生授权或文件窗口。

   逐个完成或取消自己发起的窗口；[Agent](agent.md#walkthrough-agent-tool-lifecycle-11-native-cancel-panel)和[MCP](mcp.md#walkthrough-mcp-tool-lifecycle-11-native-panel)展示实际Save取消与再次保存。它们不声称替你检查了当前所有窗口。

4. 使用 App 的 Close 正常退出；若操作忙而拒绝退出，等待完成后再关闭。

   [上节](#saved-data)已经记录 driver 执行的真实 Close 与随后真实重启。下图是关闭前状态，不能标为点击 Close 或系统恢复完成。

   ![真实 Close 发生前的画面](../media/v0.1.1-alpha.1/workspace-close/workspace-close-06-before-close.png)

   **录制边界**：[混合等待项退出](breakpoints.md#walkthrough-breakpoints-mixed-queues)已实际保留HTTP和WS等待后执行正常Close，并从客户端/源站核对取消且未转发。原生文件面板的取消见[Collection Tool](composer.md#walkthrough-composer-file-tools)。关闭前图片仍不是“进程已退出”图片，退出和系统恢复使用独立证据；不为教程故意制造Core故障或录入桌面/进程管理器。

**预期结果**：App 完成代理恢复和进程退出，不把最小化或强制结束当作正常关闭。

**关键说明**：退出不卸载 CA，不自动删除导出文件，也不保证覆盖其他软件在会话中修改的代理设置。异常时见[恢复指南](troubleshooting.md#proxy-recovery)。
