# 工作区与基本操作

> 中文初稿，面向 `v0.1.1-alpha.1`；待真实产品配图和逐步试读。以下描述桌面 App，不把官网的布局或系统主题设置套到 App。

[教程目录](../README.md) · [快速上手](getting-started.md)

<a id="navigation"></a>
## 找到需要的工具

**用途与前提**：App 已完成启动准备，从左侧导航进入对应任务。

| 入口 | 用来做什么 |
| --- | --- |
| Capture | 观察经过代理的请求、正文和消息；处理挂起的断点 |
| Rules & Map | 按条件改变后续经过代理的流量 |
| Composer | 独立构造和发送请求，管理 Collection |
| Diagnostics | 查询 App 运行记录和失败原因 |
| Settings | 管理代理、证书、偏好、模型、MCP 与更新 |
| 窗口右上角 Agent 按钮 | 打开或关闭当前工作区旁的 AI 对话面板 |

**步骤**

1. 点击左侧功能图标进入工作区。
2. 不确定图标含义时，使用窗口标题左边的菜单按钮展开侧栏，查看名称。
3. 切换到 Settings，选中需要的设置分组；离开后再回来会保留最后访问的分组。
4. 通过特定提示跳到 Settings 时，App 可能直接定位到相关分组，例如 TLS passthrough。

**预期结果**：窗口标题和主内容随选择变化；导航本身不会重发请求。

**关键说明**：Breakpoints 在 Capture 内，不是另一套独立导航。进入 Composer 或 Settings 不等于暂停 Capture；后台流量仍取决于 Recording、代理和规则状态。

<a id="layout"></a>
## 调整分栏、窗口和滚动

**步骤**

1. 拖动 Capture 的筛选、列表与详情之间的分隔条，按任务分配宽度。
2. Composer 中分别调整 Collection 宽度、请求区和响应区高度。
3. 使用窗口右上角的最小化、最大化或恢复控件；需要时拖动窗口边缘调整大小。
4. 使用滚轮、触控板或键盘阅读溢出内容；正文内部滚到边界后继续滚动外层。
5. 较长正文可以使用相应全屏入口，结束后回到原工作区。

**预期结果**：分栏随可用空间调整，不通过截掉正文来“适应”窗口。

**关键说明**：最小化不是退出，代理和录制可能继续运行。全屏正文只扩大查看范围，不解除预览字节上限，也不重新获取未被捕获的数据。

<a id="appearance"></a>
## 选择主题与语言

**步骤**

1. 在侧栏底部打开 Theme。
2. 选择 `warm`、`light`、`ember`、`dark` 中的一个主题。
3. 打开 Language，选择所需界面语言。
4. 检查界面已更新；重新启动后核对偏好保持。

**预期结果**：主题改变颜色而不改变功能；语言改变界面文案，不翻译 URL、协议、请求内容和 Tool 名称。

**关键说明**：App 提供四套时段主题和 15 种界面语言，但不代表教程已有 15 个语言版本。官网的 System/Light/Dark 与 App 的四主题不是同一个设置。

<a id="agent-panel"></a>
## 在工作区旁使用 Agent

**步骤**

1. 点击窗口右上角的 Agent 按钮。
2. 未配置模型时，从面板的配置入口进入 Settings > Agent。
3. 已配置时选择或创建 Chat；需要操作其他工具时直接切换工作区。
4. 不需要面板时，再点 Agent 按钮或面板内的关闭按钮。

**预期结果**：面板位于主内容旁边，主内容缩窄而不是被遮盖；切换工作区或进入设置不自动关闭面板。

**关键说明**：当前选中的请求不会仅因打开面板就自动加入模型上下文。与模型交换的数据边界见 [Agent](agent.md#privacy)。

<a id="saved-data"></a>
## 哪些内容会保存

| 内容 | 需要记住的规则 |
| --- | --- |
| 当前 Capture 请求与正文 | 临时记录，Core 退出或重启会释放；重要数据先导出 |
| Rules | 编辑后需要 Apply；文件导入的确认流程会直接保存追加结果 |
| Composer Collection | 编辑自动保存；Recent sends 是另一份内存记录 |
| 代理、TLS 和其他偏好 | 按各自 Apply 或设置操作保存，不由 Capture Clear 清除 |
| Agent 配置和会话 | 在本地保存；模型调用及 Tool 结果仍可能发送到模型服务 |
| 导出的文件 | 保存在用户选择的位置；Clear 不会代你删除这些文件 |

**操作建议**：退出前先完成导出、Apply 或正在进行的保存；不要仅凭屏幕还显示着数据就判断已经持久化。

不同系统账号或独立 App 数据环境之间不应假设集合和会话自动同步；当前系统用户的 CA 和代理恢复信息另有共享生命周期，不能通过随意删除 App 数据目录来重置它们。

<a id="close"></a>
## 正常结束一次使用

1. 处理或明确放弃仍挂起的断点，避免客户端一直等待。
2. 导出需要保留的流量，等待文件任务完成。
3. 确认没有尚未处理的原生授权或文件窗口。
4. 使用 App 的 Close 正常退出；若操作忙而拒绝退出，等待完成后再关闭。

**预期结果**：App 完成代理恢复和进程退出，不把最小化或强制结束当作正常关闭。

**关键说明**：退出不卸载 CA，不自动删除导出文件，也不保证覆盖其他软件在会话中修改的代理设置。异常时见[恢复指南](troubleshooting.md#proxy-recovery)。
